## 3. 💡 Background and Rationale
> *อธิบายที่มา ความสำคัญ และปัญหาที่ต้องการแก้ไข (Pain Point) เพื่อให้เห็นภาพรวมของโครงงาน*

ที่มาและความสำคัญ
ระบบ Security ส่วนใหญ่ในปัจจุบันมักจะเน้นแค่การ "ตั้งรับ" คือรอให้เกิดเรื่องก่อนถึงจะแก้ไข ทำให้เราเสียเปรียบแฮกเกอร์อยู่ตลอด ผมเลยสนใจทำ Honeypot ขึ้นมาเพื่อใช้เป็นกลยุทธ์เชิงรุก โดยการสร้างระบบจำลองมาเป็น "ตัวล่อ" ให้คนร้ายเข้ามาติดกับ เพื่อที่เราจะได้เห็นพฤติกรรมการโจมตีล่วงหน้าก่อนที่ระบบจริงจะโดนเล่นงาน

ปัญหาที่ต้องการแก้ไข (Pain Points)
อยากรู้แต่ไม่กล้าเสี่ยง: เราต้องการศึกษาพฤติกรรมของแฮกเกอร์เพื่อหาทางป้องกัน แต่การจะปล่อยให้แฮกเกอร์เข้ามาทดสอบกับระบบจริงนั้นเสี่ยงเกินไป เพราะอาจทำข้อมูลพังหรือระบบล่มได้

สรุปแนวคิด
โครงงานนี้คือการสร้าง "เป้าหลอก" ขึ้นมาเพื่อดึงความสนใจคนร้าย ทำให้เราสามารถเฝ้าสังเกตและวิเคราะห์วิธีการโจมตีได้ทุกขั้นตอน โดยที่ไม่ต้องเอาเครื่อง Server จริงไปเสี่ยง
